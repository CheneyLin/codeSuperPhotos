## 二、逐区域读稿与现状对照

### 1. 整体布局
- **稿**：整屏是一个“实体桌面微缩景”。背景是洞洞板（pegboard）墙面 + 底部木桌/搁板，桌上摆绿植与笔记本；照片像实体相纸靠在墙上；右上是侧拉相簿抽屉；左下露出一台带圆形表盘的蓝色机器；底部中央是装纸团的桶。无导航栏，状态栏直接压在场景上。
- **现状**：`Theme.Surface.base` 纯色底 + 20/60/20 三栏（`VaultDoorColumn` / `PhotoStageView` / `FavoriteAlbumColumn`）+ 底部 `DestroyDock`，新拟物（neumorphic）风格，无场景化背景。
- **差距**：从“控件面板”变成“场景 + 道具”。布局比例接近，但表现语言完全不同。

### 2. 顶栏
- **稿**：洞洞板顶部两个挂钩——左侧挂「锁 + 钥匙」，右侧挂「螺丝刀」；中间只有洞洞，没有标题、没有机器选择器、没有齿轮。
- **现状**：`HomeView.headerBar` = 左保险箱按钮 + 中 `DestroyMachineSelector`（壁炉/碎纸机）+ 右设置齿轮。
- **差距**：需把按钮改成挂钩道具；**机器选择器在稿中完全缺失**，是结构问题而非视觉问题。

### 3. 中间舞台
- **稿**：一张大尺寸白色拍立得，白边下厚上薄，带投影与轻微倾斜，画面为湖景。**只画了一张**，看不到叠层。
- **现状**：`PhotoStageView` 4 层拍立得堆叠（第 2/3/4 张分别 -15°/+10°/-5°），轻点全屏、上滑延后、下滑废纸篓、左滑保险箱、右滑收藏夹、右下角“下一张”。
- **差距**：卡片外观需重绘（白边比例、圆角、投影、倾斜）；手势语义要全部保留，但稿未表达叠层与手势提示。

### 4. 左侧保险箱
- **稿**：屏幕左缘露出一台蓝色保险柜（圆形转盘表盘），大部分在屏外，属于“场景道具”而非完整栏位。
- **现状**：`VaultDoorColumn` 占宽 20% 的黄铜门 + “待加密 n 张”计数，左滑时开门、照片飞入。
- **差距**：形态、配色、交互热区都要变；计数是否保留、放哪里需确认。

### 5. 右侧收藏夹
- **稿**：右侧一个半透明侧拉抽屉面板，顶部/底部各有一个竖向拉手，内部竖排 5 个相簿：最近项目、旅行照片（选中态：蓝色发光描边 + 蓝色文字）、我的猫咪、美食日记、花花世界。每个条目是文件夹图标 + 名称。
- **现状**：`FavoriteAlbumColumn` 占宽 20%，顶部“收藏夹”小标题，下接相簿行（文字为主）+ 延后入口 + 更多相簿入口。
- **差距**：面板材质、条目图标化、选中态发光是视觉改动；**“这是筛选器还是右滑目标”语义需要确认**。

### 6. 底部机器坞
- **稿**：底部是木桌 + 搁板，中央露出绿色纸团桶（深色稿为深蓝桶），桶口被桌沿遮住一部分；没有进度条、没有机器类型切换、没有待销毁计数。
- **现状**：`DestroyDock` 全宽面板，含机器口动画（壁炉/碎纸机）、待销毁计数、“本批结束后统一删除”说明。
- **差距**：需把坞改成“桌下纸篓”的道具形态；计数与机器类型的落位未定。

### 7. 首屏 / 桌面
- **稿**：未提供。两张稿都是“工作区”状态。
- **现状**：`TaskDeskView` = 132pt 拟物图标 + 「开始」按钮；有任务时显示进度与继续/完成。
- **差距**：未知。需确认首屏是否也套用同一场景。

### 8. 弹窗与面板
- **稿**：未提供。相簿选择、结算页、全屏查看、设置、延后管理、权限引导、Onboarding 都没有出现。
- **现状**：均有实现，且视觉体系目前是新拟物 + 黄铜。
- **差距**：这些页面若只改工作区会造成风格断层，需要统一决策。

## 五、分步实施顺序

> 原则：先 token 与素材，再场景，再局部组件，最后结构与缺失页面；每步可独立验收、可回退。

**Step 1｜设计 token v2（低风险）**
- 内容：新增暖色系 palette、圆角/阴影/材质 token，保留旧 token 兼容。
- 影响：全局颜色只在新组件使用，旧页面不受影响。
- 风险：暗色模式对比度；需同步高对比度变体。

**Step 2｜图标资源接入（低风险）**
- 内容：`IconAsset` 映射 + 预览页；确认 3x 内在尺寸（约 30–60pt）在真机上的清晰度。
- 影响：纯新增。
- 风险：大图内存（24 张合计约 1MB PNG，解码后需注意）；必要时改为按需加载。

**Step 3｜场景背景层（中风险）**
- 内容：`SceneryBackgroundView` 接入 `HomeView`，关闭命中测试，适配安全区与不同屏幕比例。
- 影响：只影响工作区背景。
- 风险：窄屏/灵动岛遮挡；背景图在小屏需裁切策略；减少动态效果。

**Step 4｜顶栏挂钩化（中风险）**
- 内容：钥匙 → 保险箱，螺丝刀 → 设置；保留原 action；中间主控暂留占位。
- 影响：`HomeView.headerBar` 重写。
- 风险：可点击区域偏小；辅助功能标签需补齐。

**Step 5｜右栏抽屉化（中风险）**
- 内容：换成抽屉面板 + 文件夹图标 + 发光选中；保留滚动选择与右滑存入。
- 影响：`FavoriteAlbumColumn` 外观。
- 风险：右栏变宽后压缩舞台；发光的性能开销。

**Step 6｜左栏保险柜化（中风险）**
- 内容：蓝色柜体侧面 + 表盘，左滑开门、飞入动效映射到新形体。
- 影响：`VaultDoorColumn` 外观与开门动画。
- 风险：屏外裁切比例在不同机型不一致。

**Step 7｜底部纸篓化（中风险）**
- 内容：桌下纸篓 + 待销毁计数；保留机器口动画或改为纸团落入。
- 影响：`DestroyDock` 外观。
- 风险：桌沿遮挡导致点击热区不明确。

**Step 8｜舞台相纸重绘（低风险）**
- 内容：比例、白边、圆角、阴影；叠层角度保留。
- 影响：`PhotoStageView` 卡片样式。
- 风险：与手势位移叠加时的视觉抖动。

**Step 9｜结构决策落地（高风险，需拍板）**
- 内容：机器类型入口、任务进度、纸篓点击、右栏语义。
- 影响：可能改动 `HomeView` 结构。
- 风险：与既有任务流/手势冲突。

**Step 10｜其余页面统一（中风险）**
- 内容：首屏、相簿选择、结算、全屏、设置、延后管理套用新语言。
- 影响：多文件视觉层。
- 风险：工作量大；风格不统一会显得割裂。

**Step 11｜真机验收**
- 内容：深浅色、窄屏、动态字体、减弱动态效果、低电量、100 张任务全流程。

## 七、当前结论

- 24 个图标已切分入库，可直接使用。
- 新稿是“场景化”改版，视觉改动远大于交互改动；现有任务流、手势语义、保险箱/删除一致性可以完整沿用。
- 真正需要决策的是四个结构问题：机器选择器去留、右栏语义、任务进度位置、纸篓热区。
- 建议从 Step 1–2 开始（token 与素材），这两步不影响任何业务逻辑，便于先验证视觉方向。
