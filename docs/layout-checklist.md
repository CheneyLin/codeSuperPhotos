# 主界面布局 / 组件位置清单

基准：iPhone 16 逻辑尺寸 393 × 852（安全区上 59 / 下 34）。一期只保证 iPhone 全屏机；iPad 二期；不对 SE / mini 做布局兜底。

数值来源：`Features/Home/DeviceLayoutConfig.swift`（多设备总配置）、`HomeView.taskWorkspace` / `workspaceColumns`、`LCDSpec`、`Theme.Spacing`、`Theme.Metrics`。

## 2. 四个验收尺寸（公式推算）

| 机型 | 逻辑尺寸 | safeTop | LCD | 左右按钮区 | 保险箱 / 收藏夹 / 中栏 | 预期 |
| --- | --- | --- | --- | --- | --- | --- |
| iPhone 16 | 393 × 852 | 59 | 240 × 140.3 | 68.5 / 68.5 | 78.6 / 88.6 / 195.8 | LCD x≈76.5…316.5；按钮中心 x≈42.3 / 350.7 |
| iPhone 16 Pro | 402 × 874 | 62 | 240 × 140.3 | 73 / 73 | 80.4 / 90.4 / 201.2 | 同上；行高增加来自高度差 |
| iPhone 16 Pro Max | 440 × 956 | 62 | 240 × 140.3 | 92 / 92 | 88 / 98 / 224 | 两侧最宽，按钮离 LCD 最远 |
| 430 × 932 机型 | 430 × 932 | 59 | 240 × 140.3 | 87 / 87 | 86 / 96 / 218 | 无 17.6 以下系统真机时按公式验收 |

> 按钮区宽度 = `(屏宽 − 2×8 − LCD 宽) / 2`；窄屏下先保住两侧 64pt，再按 `min(displayWidth, 屏宽 − 16 − 128)` 收缩 LCD（`displayWidth` 现为 260，由用户调整）。

三栏行高度 = `容器高 × 中区权重 / 权重和 − bannerHeight`；上 / 下区分别由 `padding(.top)` / `padding(.bottom)` 让出，三段之和恒等于容器高。默认权重 `0 : 1 : 0`（`DeviceLayoutConfig.fullMiddleZones`）等价于旧「1.44 倍被屏高钳住」的视觉结果；改权重即可给顶栏留白 / 道具区让带，例如 `1 : 7 : 2`。行高不再由台面线、纸篓高度或 `dockBudget` 反推。

三栏宽度公式：`usableW = rowW − 14 − 16`，`side = min(148, max(56, rowW×0.2))`，`favorite = min(168, max(64, side+10))`，`middle = usableW − side − favorite`；`middle < 120` 时两侧按 45% 预算收缩。

## 3. 验收要点

1. 桌面态 / 处理态切换时，顶部整行高度恒为 152pt，三栏行的上沿、照片堆叠锚点、纸篓位置**零位移**；只有左右按钮内容与 LCD 内部文字变化。
2. LCD 与两侧按钮不重叠：393 宽屏上按钮右缘约 74pt、LCD 左缘约 76.5pt，留约 2.5pt 净空；受限授权提示条挂在三栏行上方，不顶到顶栏。
3. 回退 / 结束按钮中心与桌面态挂件同轴（x≈42.3 与 350.7，误差 ≤ 1pt），垂直方向与 LCD 屏面同心，不压屏体、不进入中栏手势区。
4. 深色模式、放大字号、横竖图混排下，屏内三行不溢出玻璃框；提示文案先缩到 65%，仍超长才尾部省略。
5. 三区权重生效后：三栏行顶落在「上区」末尾、行底落在「下区」起点，命中调试的蓝色中栏框 / 绿色右栏框同步变化；照片堆叠与「开始」按钮在新行内居中，不被裁切。默认 `0 : 1 : 0` 下 HUD 的 `form` 行应显示当前形态，且 `contentBottom ≈ 容器高`；改成 `1 : 7 : 2` 后真机重点看上区留白与道具区是否仍不压三栏。
6. 底部道具连点 5 次按「废纸篓 → 碎纸机 → 壁炉 → 邮筒 → 任意门」循环；切换弹跳、五点指示与名称牌都不改变 `dockHeight`，台面线、纸篓下移量、三栏落点与升级前一致；系统「降低动效」开启时切换只剩淡化、常驻粒子静止。

## 4. 适配范围

- 一期：只保证上表四个 iPhone 全屏机尺寸。
- iPad / Duo：沿用同一套公式；`DeviceForm.current(...)` 按铰链状态 + 窗口宽高 + `userInterfaceIdiom` 判定七种形态，每种形态在 `DeviceLayoutConfig` 里各占一行，不新增尺寸断点。
- SE / mini：放弃布局验收；代码保留 `max(0, …)` 与 `max/min` 钳制，只保证不出现负尺寸、不崩溃。

## 5. 多设备布局配置（手工调整）

配置文件（唯一入口）：`source/appSuperPhotos/SuperPhotos/Features/Home/DeviceLayoutConfig.swift`

| 项 | 含义 |
| --- | --- |
| 七个 `DeviceLayoutEntry` | iPhone 横 / 竖、iPad 横 / 竖、Duo 外屏 / 内屏横 / 内屏竖，各一行；改哪行只影响哪个形态。`all` 的顺序即预览图 / HUD 的顺序 |
| `background` | 浅 / 深两张背景成品图的 Asset Catalog imageset 名。换图：新图拖进 `Assets.xcassets/Scenery` → 改字符串；名字写错或图未导入自动回退 `SceneryAssets.standard`。图片宽高比由 `UIImage.size` 实读，不用填尺寸 |
| `favorites` | `rows` 一屏可见行数（不截断真实相簿）、`iconSize` 文件夹图标边长 pt、`titleSize` / `badgeSize` 字号；实际图标仍受栏宽与行高钳制 |
| `zones` | 上 / 中 / 下三区高度权重，任意非负数、自动归一化、不要求和为 1。默认 `(0, 1, 0)` 中间区占满；`(1, 7, 2)` 即 10% / 70% / 20% |

调整流程：改数值 → `python3 design/background-v4/preview_device_layout.py` 看 `/tmp/device_layout_preview.png`（脚本正则读 Swift 配置，不维护第二份数值，同时给出三区比例的三种取值示意）→ Run 到真机复核。DEBUG 用 `SP_DUO_STATE=closed|fullyOpen|partiallyOpen` 模拟 Duo 姿态，右上角 HUD 的 `form` 行显示当前生效形态，调参前先确认这一行。**没有 Y 轴位移，也没有自动模式**：背景恒顶部对齐，宽屏看不到桌面时靠换专用背景图或调 `zones` 解决。
