## 中间区（三栏工作区）高度 +20%

- 用户自行把 `LCDSpec.displayWidth` 从 240 调到 260、注释掉 `PegboardHookButton` 的挂钩、给左上挂件和 LCD 各加了 offset，并给出发着命中调试框的真机截图（中栏蓝框约 214…542pt，台面线约 735pt，中间有大段空白）。
- `HomeView` 新增 `private static let workspaceHeightScale: CGFloat = 1.2`：`baseRowHeight = max(0, contentBottom − bannerHeight)`、`rowHeight = baseRowHeight × 1.2`，`extraRowHeight` 从 VStack 的 `.padding(.bottom, max(0, size.height − contentBottom − extra))` 让出，使增量向下延伸。行顶、台面线、纸篓、背景锚点、`contentBottom` 基准都不动；倍率改回 1 即恢复。

- 顺带修 `HitDebug.swift`：`LayoutProbeKey.reduce` 原为无条件 `value = nextValue()`，被没有上报的兄弟分支的 defaultValue（全 0）覆盖，导致真机 HUD 的 LAYOUT 全 0.0（区域框正常，因为 `HitDebugRegionKey` 是字典 merge）。改为 `guard next.rowW > 0 else { return }`。

## 中间区再加 20%（累计 1.44 倍）

- 用户看完 1.2 倍效果后要求「再加20%」，按相对当前再乘 1.2 理解：`workspaceHeightScale` 1.2 → 1.44（累计 +44%）。若要累计 1.4 只需改常量。
- `rowHeight` 计算改为 `baseRowHeight + min(baseRowHeight × (scale − 1), availableDrop)`，`availableDrop = max(0, size.height − contentBottom)`；增量受「内容底 → 容器底」余量钳制，防止继续调大倍率时 VStack 比容器高、行顶顶进 LCD 区，同时 padding 保持 ≥ 0。
- 文档同步 `product-plan.md` 4.1/4.2、`layout-checklist.md`、`decision-log.md` #143；顺手把 checklist 里「列高 = 行高 × 1.2」这类含糊写法改成「实际 rowHeight = 基准 × 1.44」。
